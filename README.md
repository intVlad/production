# MES — система керування виробництвом

Облік виробництва в цеху: моделі виробів і маршрути їх виготовлення, серії замовлень,
завдання на постах, облік матеріалів, брак, аутсорс і журнал усіх дій.

Три робочі місця, усі в браузері:

| Екран | Для кого | Що робить |
|---|---|---|
| `manager.html` | менеджер, диспетчер | планування серій, дашборд, склад, персонал, брак, аудит |
| `worker.html` | оператор на планшеті | сканує пост або піддон, бере завдання, веде час, фіксує брак |
| `tv.html` | екран у цеху | показ статистики без вводу, слайди змінюються самі |

**Стек:** Java 17 + Spring Boot 3 (API), звичайні HTML/CSS/JS без фреймворків (інтерфейс),
PostgreSQL у продакшені та H2 у розробці.

## Швидкий запуск для розробки

Потрібна лише Java 17+. База не потрібна — піднімається H2 в пам'яті з демо-даними.

```bash
cd backend && ./mvnw spring-boot:run     # API на :8080
cd frontend && python3 -m http.server 8000   # інтерфейс на :8000
```

Відкрити <http://localhost:8000>. Демо-акаунти (лише в режимі розробки):

| Роль | PIN |
|---|---|
| Менеджер | 7777 |
| Адміністратор | 9999 |
| Диспетчер | 5678 |
| Робітник (Іван) | 1234 |
| ТВ-екран | 0000 |

Дані живуть у пам'яті й зникають при перезапуску — це навмисно.

```bash
cd backend && ./mvnw test     # 260 тестів
```

## Розгортання

В обох варіантах API та інтерфейс віддаються **одним сервісом**: браузер завантажує сторінки
й звертається до `/api` того самого домену. Тому CORS не потрібен узагалі, а платити треба
за один сервіс, а не за два.

### Railway

1. Створити проект з репозиторію на GitHub. Railway підхопить `railway.json` і `Dockerfile` сам.
2. Додати в проект **PostgreSQL** (`New → Database → PostgreSQL`).
3. У сервісі застосунку задати три змінні:

   | Змінна | Значення |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_PRIVATE_URL}}` |
   | `JWT_SECRET` | результат `openssl rand -base64 48` |
   | `APP_BOOTSTRAP_ADMIN_PIN` | PIN на ваш вибір, **тільки для першого запуску** |

   Подвійні фігурні дужки — це посилання Railway на сервіс бази; підставить значення сам.
   Якщо ваш сервіс бази названо не `Postgres`, підставте його назву.

   Адресу застосунок переведе у формат JDBC самостійно. `DATABASE_PRIVATE_URL` — внутрішня
   адреса: трафік не виходить назовні, тож це швидше й не тарифікується як вихідний.
   Якщо з нею з якоїсь причини не з'єднується, тимчасово підставте `${{Postgres.DATABASE_URL}}`.

4. Дочекатись розгортання, відкрити виданий домен, увійти під `APP_BOOTSTRAP_ADMIN_PIN`.
5. Створити справжні акаунти через «Персонал», змінити PIN адміністратора,
   **видалити змінну `APP_BOOTSTRAP_ADMIN_PIN`**.

Далі кожен `git push` у `main` розгортається автоматично. Railway піднімає нову версію,
опитує `/actuator/health/readiness` і перемикає трафік лише коли вона готова — старі
запити при цьому доробляють (див. `server.shutdown: graceful`).

### Свій сервер

```bash
cp .env.example .env    # заповнити
docker compose up -d
```

Інтерфейс на порту 8080. База назовні не публікується.

## Змінні оточення

| Змінна | Обов'язкова | Що робить |
|---|---|---|
| `DATABASE_URL` або `DATABASE_PRIVATE_URL` | на платформах | Адреса бази у форматі `postgresql://user:pass@host:5432/db` — саме так її видають Railway, Render і Heroku. Переводиться у JDBC автоматично. |
| `SPRING_DATASOURCE_URL` | альтернатива | Готова JDBC-адреса. Якщо задана — має пріоритет над попередньою. Без жодної з них — H2 в пам'яті. |
| `SPRING_DATASOURCE_USERNAME` / `_PASSWORD` | з `SPRING_DATASOURCE_URL` | Доступ до бази. При `DATABASE_URL` беруться з неї. |
| `JWT_SECRET` | **так**, якщо база постійна | Ключ підпису токенів. Без нього застосунок **не стартує**. Зміна — розлогінює всіх. |
| `APP_BOOTSTRAP_ADMIN_PIN` | для першого запуску | Створює одного адміністратора, поки база порожня. |
| `APP_CORS_ALLOWED_ORIGINS` | ні | Потрібна, лише якщо інтерфейс віддається окремим доменом. |
| `APP_SEED_DEMO_DATA` | ні | `true` сіє демо-дані з PIN-ами з цього файлу. **Ніколи в продакшені.** |
| `PORT` | ні | Платформа задає сама. |

## Що варто знати при обслуговуванні

**Схема бази.** Оновлюється автоматично при старті (`ddl-auto: update`). Для поточного етапу
цього достатньо, але це означає: зміни, що ламають сумісність (перейменування чи видалення
колонки), потребують окремої уваги, бо під час оновлення стара й нова версії коротко
працюють одночасно. Коли зміни схеми стануть регулярними — час переходити на міграції (Flyway).

**PIN унікальний для всіх акаунтів.** Це навмисно: на екранах «Менеджер» і «ТВ» вхід
відбувається лише за PIN, тож він і є посвідченням особи. Спроба задати зайнятий PIN
відхиляється з поясненням.

**Бекапи.** Railway робить їх сам. На своєму сервері це ваша відповідальність:
`pg_dump` за розкладом і копія **поза** цим сервером.

**Живі оновлення.** Дашборд і ТВ-екран оновлюються самі через SSE. При розгортанні
з'єднання обривається й відновлюється автоматично; індикатор у бічній панелі показує
реальний стан зв'язку.
